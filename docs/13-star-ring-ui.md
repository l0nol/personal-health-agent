# 星环首页（Chronos Ring）：设计与实现

> 2026-10-25 重做。把默认首页从"一堆指标卡平铺"改成**以中央状态核心为中心的环形导航**：
> 默认只给一个结论和一圈安静的入口，用户指到哪个模块，那个模块的摘要才展开。
>
> 一句话原则：**默认简洁，交互后展开；环形负责探索，页面负责细节。**

---

## 1. 为什么这么改

旧首页（`index.html`）把所有东西同时摊开：建议卡 + 4 张指标卡 + 睡眠图 + 待处理 +
快速记训练 + 最近记录。信息都真实，但第一眼没有焦点——打开就想找"我今天到底怎么样"，
眼睛要先在六块内容里挑。

新版首页只回答一个问题：**今天大概处于什么状态**（来自既有规则引擎的分类判断），
其余五个模块以"可探索的光点"存在，指过去才展开。原来的详细列表没有被删：
`设置 → 外观 → 详细列表` 随时切回，它仍然是找明细最快的地方。

## 2. 环上有什么

| 位置 | 模块 | 中心显示 | 展开面板 |
|---|---|---|---|
| 12 点 | 睡眠 | 昨夜睡眠时长 | 近 7 天柱状图（含目标线）、睡眠阶段、参照与目标说明 |
| 2 点 | 恢复 | 静息心率 | 个人基线区间、HRV、睡眠血氧、呼吸率、今天的主观反馈、14 天心率走势 |
| 4 点 | 训练 | 今日建议类别 | 本周次数、最近一次、4 周次数柱状图、建议与边界 |
| 6 点 | 报告 | 已确认记录数 | 当日简报正文（本地模板生成）、数据截至、待确认数 |
| 8 点 | 助手 | 接口是否可用 | 接口状态、对话条数、快捷问题、去设置 |
| 10 点 | 趋势 | 有数据的指标数 | 每个指标一张迷你走势图（4 行） |

闲置状态（刚打开时）：中心显示「今日状态 · 分类标签」，右侧只放**一张**「今日建议」卡
（复用 `_macros.guidance_card`，依据/为什么/边界都在），指针隐藏。

> 「恢复」不是独立页面：它把静息心率、HRV、主观反馈放在一起看，详情落到趋势页的心率视图。
> 为一个模块再造一页重复内容，只会让两个地方的数字有机会不一致。

## 3. 交互：零 JS 可用，脚本只做增强

结构是**原生单选控件 + label**：

```
input.ring-input × 7（6 模块 + 闲置）  →  .ring-stage（环 + 面板）
```

- 点模块圆点/标签 = 选中并展开对应面板（`label for` 触发 `change`）；
- Tab 进环后用方向键换模块（浏览器原生 radio 行为），焦点环画在**用户看得见的圆点**上；
- 面板里的按钮才跳转——模块本身不跳转，避免"以为在看预览，其实已经离开页面"。

`change` 之后 CSS 只做三件事：把 `--deg` 换到该模块角度（指针 + 高亮弧）、
把 `--mod` 换成该模块色、显示对应的 `core-card` 与 `panel`。

**脚本（约 80 行，块内唯一一段）只补两件 CSS 做不到的事：**

1. **指针走最短路径**：从 300° 到 0° 时，CSS 的 transition 会倒着扫 300°，
   脚本维护一个累计角度，位移永远 ≤180°；
2. **按住环身拖拽**：跟手转动指针，松手吸附到最近模块；拖拽只改选中，不做导航。

没有脚本时：点击、方向键、面板展开、指针角度（CSS 里逐模块写死的 `--deg`）全部照常。

## 4. 视觉规则（为什么不是"满屏发光"）

- **底色**：深海蓝偏近黑的藏蓝（`#060B14`），不是纯黑——纯黑会让玻璃质感失效；
- **层次**：亮度差 + 1px 描边 + 极轻的内阴影，不靠大块投影；
- **光只给焦点**：外环 `box-shadow` 只在选中时亮；中央光只在呼吸，不位移；
- **一个模块一个色**（`--c-sleep` / `--c-recovery` / …），颜色只表示"这是哪个模块"，
  不代表健康状况，也不给任何评分着色；
- **动效清单**（全部 `transform` / `opacity`，无 layout 抖动）：
  中央光呼吸 8s、光环流动 44s、指针 0.62s 缓动、面板 0.46s 浮起、节点放大 0.3s；
- **`prefers-reduced-motion: reduce`** 下：动画 `none`、过渡 `none`，指针直接落位。

## 5. 数据口径（这次没有新口径）

所有数字来自原有统计函数，`ui/context.py` 只是换排布：

| 面板 | 数据来源 |
|---|---|
| 睡眠 | `summarize(night_sleep_minutes)` + `build_bars` + 阶段占比（`deep/light/rem`） |
| 恢复 | `summarize(resting_hr_bpm)` + `reference()`（28 天 / ≥14 天 / 2.5×MAD）+ `hrv_avg_ms` 等 + `training_store.get_feedback` |
| 训练 | `training_store.count_sessions/list_sessions` + `build_guidance()` 的类别与依据 |
| 报告 | `build_daily()` 的正文、`count_records` 的计数 |
| 助手 | `settings.ai_enabled` + `chat_store.load`（只读，GET 不发网络请求） |
| 趋势 | 4 个指标的 14 天序列 + `build_spark` |

硬约束（回归测试守着）：

- **不造健康总分**：中心只有分类标签或一个真实指标值，"综合评分"这类词在页面上不存在；
- **缺失不是 0**：没有就写「—」，折线断开、柱状空心；
- **数据不足就说数据不足**：`guidance` 判为 `insufficient_data` 时，中心直接显示「数据不足」；
- **AI 没配置就写未配置**，不给假对话；GET 打开页面永远零网络。

## 6. 响应式

| 宽度 | 布局 |
|---|---|
| ≥1280 | 侧栏 + 环（≤520px）+ 面板（400px）并排；stage 最宽 1180px，避免宽屏拉散 |
| 1024–1279 | 面板变窄（300–348px），环 270–440px，仍并排 |
| <1024 | 单列：环在上、面板在下（`display` 切换，一次只渲染一张）；导航改成一行横向滚动 |
| ≤767 | 环 84vw；未选中模块只留标签（数值只在选中时出现），圆点 40px |
| 低高度横屏（≤620px 高） | 环按 52vh 收敛，优先保证完整可见 |

实测无横向滚动：600 / 768 / 1024 / 1280 / 1440 / 1920 六个宽度。

## 8. 已知限制

1. **没在真机平板上验证过**：只在无头 Chrome 的 1280×800 / 800×1280 视口下量过，
   联想浏览器（Chromium 内核）未实测；
2. **拖拽在触屏上是 `touch-action: pan-y`**：竖向滚动手势仍然归页面，横向拖拽才转到环上；
   手指斜着拖时可能被浏览器判成滚动——所以点击才是主路径；
3. **面板内容超出时是内部滚动**（桌面），不做"高度随内容动画"，因为那会让页面跳动；
4. 环上模块固定六个：加**页面**不会自动进环，换**模块**要改 `RING_MODULES` + 面板装配；
5. 星环只在 `chronos`（默认）模式出现；详细列表模式仍是原来的浅色信息密度版式
   （深色 token 同样生效，但信息结构没动）。

## 9. 与旧版（T11 拨盘）的差异

| | T11 拨盘 | 星环首页 |
|---|---|---|
| 刻度 | 睡眠/趋势/训练/提醒/报告/设置（都是页面） | 睡眠/恢复/训练/报告/助手/趋势（**模块**，含无独立页面的"恢复"） |
| 中心 | 每个刻度一段预览 + 「进入」按钮 | 先给"今日状态"结论；选中后换成该模块摘要 |
| 助手 | 中心球 + 底部抽屉 | 作为第六个模块，面板内直说"是否已配置" |
| 指针 | CSS 逐刻度 rotate（可能倒着扫） | 脚本最短路径 + 拖拽跟手 |
| 主题 | 浅色 | 深色（星环页与全站统一） |
| 默认首页 | 简单仪表盘 | **星环**（详细列表可在设置切回） |
