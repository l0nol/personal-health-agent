### 1.2 技术现状

- **服务端渲染**：FastAPI + Jinja2，10 个模板共 632 行，`base.html` 提供导航与 flash。
- **样式**：单文件 `app.css`，176 行，10 个 CSS 变量，**只有 1 个断点**（`max-width: 640px`）。
- **图表**：**没有**。唯一的"趋势"是 `/reports` 里一张 4 行 HTML 表。
- **状态可视化**：`<span class="tag pending">` 等 6 个标签类，无图例、无颜色语义说明。
- **交互**：无 JS 框架、无 fetch；所有写操作是 `<form method="post">` + CSRF 隐藏域。
- **空/错误态**：靠 `?msg=` / `?error=` 查询参数 flash，没有页面级空状态设计。

### 1.3 已有 vs 目标（六页）差距

| 目标页 | 现状 | 差距 |
|---|---|---|
| ① 首页仪表盘 | 有 `/`，但是"计数 + 两张表" | 缺今日摘要、缺趋势缩略、缺待处理主次层级 |
| ② 睡眠分析 | **没有独立页** | 睡眠只在报告里占一句话；缺时长趋势、阶段结构、缺失可视化 |
| ③ 指标趋势 | **没有图表页** | 缺多指标折线、区间带、范围选择、覆盖率联动 |
| ④ 数据导入 | 有，且功能完整 | 视觉层级弱：五桶与文本摘要混排，操作条不固定 |
| ⑤ 提醒中心 | 有 | 缺筛选/历史、缺"为什么没有提醒"的空状态、缺规则说明 |
| ⑥ 设置与隐私 | 有 | 缺"数据与隐私"分区（备份/删除/本地存储声明）、缺外观模式入口 |

### 1.4 现有实现的可用部分（不重写）

- `base.html` 的导航 + flash + footer 结构可保留，只做分组与视觉升级。
- 所有 `<form>` + `csrf` 隐藏域严格沿用，**不改动作地址**。
- 五桶预览的数据结构（`ImportPreview`）直接驱动新视觉，不需要新接口。
- `tag` 类族可扩展为完整状态体系，而不是推倒配色。

## 2. 设计原则（每条都能对应到具体约束）

1. **数据先于装饰**：任何视觉元素若不能帮助理解数值，就不加。
2. **状态不可隐藏**：每条数值旁必须有状态与时间范围，宁可拥挤也不含糊。
3. **缺失就是缺失**：图中断线、表中"—"，绝不用 0 或平滑曲线填补。
4. **不造总分**：不出现"健康分 87"这类无依据聚合。
5. **不做假控件**：阈值只能改 `.env`，页面就显示只读值 + 说明，不放看起来能改的滑块。
6. **触控优先于悬停**：平板没有 hover，所有操作必须可点按。
7. **降级可用**：禁用 JS 时，导航、表单、图表（静态 SVG）仍可用。

## 3. 设计系统

### 3.1 颜色

**底色（浅色、偏冷的白）**

|---|---|---|
| `--bg` | `#F4F7F9` | 页面底色 |

| `--line-strong` | `#C3D2DC` | 输入框聚焦前、表格外框 |

**文字**

| Token | 值 | 对比度（对 `#FFF`） | 用途 |
|---|---|---|---|
| `--text` | `#0E1F2A` | 15.8:1 | 正文、数值 |
| `--text-2` | `#4C6473` | 6.1:1 | 次要说明、表头 |
| `--text-3` | `#7C93A1` | 3.6:1 | 仅用于 ≥16px 或非关键信息 |

**主色（深海蓝）与辅助色（青绿）**

| Token | 值 | 用途 |
|---|---|---|
| `--primary` | `#0F3D5C` | 主按钮、选中态、主折线 |

| `--accent-soft` | `#E0F2EF` | 已确认标签底 |

**语义色（克制使用，不做"健康红绿灯"）**

| Token | 值 | 用途 |
|---|---|---|

| 层级 | 字号/行高 | 字重 | 用途 |

### 3.3 间距与栅格

- 基准 4px：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`
- 卡片内边距：桌面 20，平板 16
- 卡片间距：24（桌面）/ 16（平板）
- 页面边距：32（≥1280）/ 24（768–1279）/ 16（<768）
- 内容最大宽：1200（正文段落 760）
- 桌面 12 列（gap 24）；平板 8 列（gap 16）。

### 3.4 圆角、阴影、边框

| Token | 值 | 用途 |
|---|---|---|
| `--r-card` | 12px | 卡片 |
| `--r-control` | 8px | 按钮、输入框、标签 |
| `--r-pill` | 999px | 状态标签 |
| `--shadow-1` | `0 1px 2px rgba(14,31,42,.06)` | 卡片默认 |

### 3.5 卡片

统一结构：`标题行（标题 + 右侧状态/操作）→ 主体 → 脚注（单位/窗口/来源）`。

- 数值卡：Display 数值 + 单位 + 一行"较 7 日均值 ±X" + 右下角状态点
- 图表卡：标题 + 时间范围切换（7/30/90 天）+ 图 + 脚注（有效天数/缺失率）
- 列表卡：表头 + 行 + "查看全部"

### 3.6 按钮

| 层级 | 样式 | 用途 | 触控尺寸 |
|---|---|---|---|
| Primary | 深海蓝实底白字 | 每屏最多 1 个（导入/写入/确认） | 40×40 起 |
| Secondary | 白底 + `--line-strong` 边 | 次要操作（筛选、切换） | 40 |
| Ghost | 无底无边，青绿文字 | 行内操作（确认/驳回） | **≥44×44 触控区**（视觉可小） |
| Danger | 白底红字红边 | 删除、撤销 | 40 |

按钮禁用态：40% 不透明 + `cursor: not-allowed`，并保留 title 说明原因。

### 3.7 状态标签（关键：两套语义必须分开）

**A. 记录状态（`records.verification_status`）**

| 状态 | 视觉 | 含义 |
|---|---|---|
| `pending` | 琥珀底 + 实心点 | 采集到但人未确认；**不进趋势** |
| `confirmed` | 青绿底 + 对勾 | 已人工确认；可进趋势 |
| `rejected` | 灰红描边 + 叉 | 已驳回；仅留档 |
| `superseded` | 灰底 + 时钟 | 被新版本替代；历史可查 |

**B. 指标定义可信度（`metrics.verification`）** —— 这是**定义**的可信度，不是数据状态，两者不得混用同一色系：

| 值 | 视觉 | 含义 |
|---|---|---|
| `provisional` | 虚线边框 + 灰色问号 | 单位/值域按通用范围拟定，未与设备核对 |
| `device_verified` | 实线边框 + 青绿盾牌 | 已逐字段核对 |

**C. 数据充分性（`MetricSummary.status`）**：`ok` / `insufficient` / `no_data`，用文字 + 灰阶圆点，不用红黄绿。

**D. 提醒严重度**：`info`（蓝）/ `warn`（琥珀），标签文字用规则名而非等级词。

### 3.8 图表规范（原生 SVG，无依赖）

| 图型 | 用途 | 规则 |
|---|---|---|
| 折线 | 单指标日趋势 | 2px 描边；缺失日**断线**并在 x 轴画空心点；不插值、不补 0 |
| 柱状 | 睡眠时长（离散日值） | 缺失日为空心柱；目标线为虚线并在图例写来源 |
| 区间带 | HRV / 血氧上下限 | 只画 `min–max` 半透明带 + 两条细线，**禁止**画中间实线（那就是伪造平均值） |
| 迷你走势 | 首页卡片 | 高 32px，仅主色，无坐标轴，hover/点按显示当日值 |
| 堆叠条 | 睡眠阶段 | 仅当设备提供各阶段分钟或比例；缺一项就留缺口，不归一化 |

统一要求：

- Y 轴顶部标单位（`分钟` / `次/分` / `%` / `毫秒`）
- X 轴标范围（`2026-09-20 ~ 2026-10-19`），窗口 > 14 天按周聚合刻度
- 右上角固定 `数据范围` 与 `有效 N/M 天`
- 颜色：主序列 `--primary`，对照序列 `--text-3`，参考线 `--line-strong` 虚线
- 不画"目标区间"的红色警示带；超范围用卡片右下角 `out_of_range` 文字标记

### 3.9 空 / 加载 / 错误 / 无权限

| 状态 | 设计 |
|---|---|
| 空 | 图标 + 一句解释 + 一个主操作（如"去导入"）；说明**为什么空**（没数据 / 数据不足 / 未确认） |
| 数据不足 | 琥珀条：`近 7 天仅 2/7 天有效，不做趋势判断`，下方只展示原始值 |
| 加载 | 骨架块（`--surface-2`），不用转圈 |
| 错误 | 页面级：标题 + 原因 + 返回；表单级：字段下方红色 12px 文案 |
| 无权限 | 保持现有 303 → `/login`，不做前端拦截 |

## 4. 六个页面

> 所有页面共用：顶部标题区（标题 + 副标题 + 主操作）、数据状态图例（首次进入显示一次）、页脚免责声明。

### 4.1 首页仪表盘 `/`

```
┌ 顶部：今日摘要 ────────────────────────────────┐
│ 10 月 19 日 · 周一     已确认 4/6 项   [导入数据] │
├ 4 张数值卡（2×2 平板 / 4×1 桌面）──────────────┤
│ 睡眠 6h53m 目标 7h(默认参考值)  │ 静息心率 59   │
│ 步数 8,260       活动热量 417 kcal              │
├ 睡眠结构卡 ──────────────┬ 待处理 ──────────────┤
│ 深睡 21% 浅睡 54% REM 25% │ 待确认 3 · 冲突 1 · 未读 2 │
│ (缺失项留空，不归一化)     │ 每项可点进对应页       │
├ 近 7 天迷你走势（每指标一行）──────────────────┤
└ 页脚：数据截至 2026-10-19 · 仅趋势观察，不构成诊断 ┘
```

- **主操作唯一**：`导入数据`（Primary）。
- 数值卡右上角状态点：青绿=已确认，琥珀=含待确认，灰=无数据。
- 目标对比必须标注来源：`目标 7h（默认参考值）` 或 `目标 8h（你设定）`；年龄未知时不得写"按你年龄推荐"。
- 不做"健康总分"。

### 4.2 睡眠分析 `/sleep`（新增只读页）

```
标题：睡眠分析
范围：[7 天] [30 天] [90 天]        目标：7h（默认参考值 ⓘ）
┌ 主图：每日夜间睡眠时长（柱）+ 目标虚线 + 缺失空心柱 ┐
├ 睡眠阶段卡（仅当设备提供）                        ┤
│ 深睡 ███ 21%   浅睡 ███████ 54%   REM ███ 25%     │
│ 若只提供比例 → 不换算分钟；若只提供分钟 → 不换算比例 │
├ 明细表（最近 14 天）                              ┤
│ 日期 | 时长 | 深/浅/REM | 状态 | 来源 | 修正        │
└ 脚注：有效 5/7 天 · 缺失 2 天 · 数据不足时不做趋势判断 ┘
```

- 空数据：整页一句"还没有睡眠数据"+ 去导入。
- 数据不足（<3 天）：主图上方琥珀条，数字照常显示但不给"平均/趋势"。
- 睡眠评分等设备原值：显示但标注 `设备原值`，不做二次解读。

### 4.3 指标趋势 `/trends`（新增只读页）

- 左侧（桌面）/ 顶部（平板）指标选择器：按 P0 / P1 分组，`provisional` 指标带虚线问号。
- 范围：7 / 30 / 90 天；切换只改查询参数，服务端渲染。
- 主图按指标类型自动选择：数值→折线；`range_bound`→区间带（HRV/血氧）；计数→柱。
- 统计条：均值 / 中位 / 最小 / 最大 / 有效天数 / 缺失率 + `status` 文案。
- 固定提示：`仅统计已确认（confirmed）记录；周/月视图记录不参与日趋势。`
- 若当前指标是 `range_bound`：顶部常驻一行 `该指标为区间端点，没有平均值，也不会被计算。`

### 4.4 数据导入 `/imports` 与预览

- 三步条：`① 上传 → ② 预览（不写库）→ ③ 写入（全部 pending）`，当前步高亮。
- 预览页五桶改为**横向计数条 + 分区表格**，顺序按"需人处理"优先：冲突 → 待复核 → 拒绝 → 重复 → 可直接确认。
- 每行显示：行号、指标（中文名+字段名）、原始值→归一值、单位、错误码/标记、原因。
- 底部**固定操作条**：`写入 N 条（全部为 pending）` + 说明"写入后仍需在记录页确认"。
- 拒绝区提供"复制错误码"文本，方便反馈。

### 4.5 提醒中心 `/alerts`

- 顶部：未读数、`立即评估`、筛选（全部 / 未读 / 按规则）。
- 卡片：规则名徽标 + 窗口 + 触发原因 + 建议 + `依据 N 条记录`（可展开）+ 三条反馈。
- 右侧（桌面）或底部（平板）常驻说明卡：`同一窗口同规则只提醒一次，冷却 72 小时`。
- 空状态分两种文案：**从未评估**（"点立即评估"）vs **评估过但无新增**（"数据不足或已在冷却期"）。

### 4.6 设置与隐私 `/settings`

分区顺序：

1. **外观**：模式 A / 模式 B（Chronos）切换 —— 阶段 2 实现，本轮只留位置与禁用说明。
2. **睡眠目标**：只读显示 `默认参考值 7 小时（未按年龄调整）` 或 `你设定 8 小时` + 如何修改（改 `.env` 重启）。
3. **生活背景**：现有 6 项，保持"全部可跳过"。
4. **提醒阈值**：只读（环境变量），附当前生效值表。
5. **数据与隐私**：导出 CSV/JSON、备份、恢复、删除说明；明确"数据只在本机，AI 只发送已算好的摘要"。
6. **关于**：版本、schema 版本、AI 是否配置、数据库路径。

**不做**：不放在页面上能改阈值的假滑块；不做"一键优化"按钮。

## 5. 响应式方案

| 断点 | 目标设备 | 导航 | 栅格 | 卡片 | 表格 |

- 所有可点元素命中区 ≥ 44×44（视觉可以更小，用 padding 扩张）。

- 表单控件不依赖 hover 显示操作；不使用的按钮不要灰着占位。
- 桌面鼠标 hover 提供的额外信息，平板上必须有等效的点击路径。

## 6. 模式 B（Chronos）的结构与约束

本轮**不设计细节**，只锁定边界，避免后续实现时越界：

- **导航等价性**：表盘外环 6 个扇区一一对应模式 A 的六个页面；必须有等价的普通导航（顶部菜单或侧栏），旋转不能是唯一入口。
- **数据一致性**：表盘中心预览只能显示与模式 A 相同的数值和状态标签，不得做第二套口径。
- **降级**：`prefers-reduced-motion` 时关闭旋转动画，改为点击切换；键盘可用 Tab + Enter 完成同一路径。
- **安全**：表盘不新增写操作，确认/删除等动作仍跳转现有页面并走 CSRF。
- **状态持久化**：模式选择写入 `settings` 表（不是 cookie），服务端渲染时读取，避免闪烁。
