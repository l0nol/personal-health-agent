# 工作台总览：模块 · 布局 · 数据来源 · 交互 · 配置

> 本文是"工作台建成后"的总说明书。设计与取舍见 `docs/04-ui-design-spec-v1.md`，
> 改界面见 `docs/06-ui-extension-guide.md`，运维见 `docs/02-runbook.md`，
> 前置条件见 `docs/07-workbench-checklist.md`。

- 版本：0.1.2 ｜ 指标注册表：40 项 ｜ 测试：463 passed
- 技术栈：FastAPI + Jinja2 服务端渲染 + SQLite + 原生 SVG 图表；**零 JS**、零外部依赖

## 1. 工作台由四个功能模块组成

| 模块 | 解决什么 | 包含页面 | 关键约束 |
|---|---|---|---|
| **M1 数据入口** | 把华为截图里的数字变成可信记录，并记录训练 | 导入 `/imports`、导入预览 `/imports/preview`、记录 `/records`、训练 `/training`、冲突 `/conflicts` | 写入一律 `pending`；训练日志是主观记录；冲突不自动裁决 |
| **M2 观察与洞察** | 看趋势、看与自己的基线差多少 | 总览 `/`、睡眠 `/sleep`、趋势 `/trends` | 只读；NaN/缺失不补 0；不做"健康总分" |
| **M3 提醒与报告** | 把数据变成可行动的提示与可回看的报告 | 提醒 `/alerts`、报告 `/reports` | 提醒是提示不是诊断；同一规则 72h 冷却；报告数字全部可追溯 |
| **M4 设置与隐私** | 配置、模式切换、数据出口 | 设置 `/settings` | 阈值只读（环境变量）；导出 CSV/JSON；删库只能手动 |
| 辅助外壳 | 另一套导航排版 | 时钟模式 `/chronos` | 六刻度拨盘 + 中心助手；预览与简洁模式同一取数函数；拖拽为可选增强 |

**一句话数据流**：截图 → 导入（pending）→ 逐条确认（confirmed）→ 统计/基线 → 趋势与报告 → 提醒。

## 2. 页面布局（逐页）

### 2.1 总览 `/`（首页）
```
顶栏：今日摘要 · 数据截至日期 · 待处理入口
4 张指标卡（2×2 / 4×1）：昨夜睡眠 · 静息心率 · 步数 · 活动热量
  └ 每卡：数值 + 状态点 + 「参照范围」行 + 近 7 天有效 N/7 天
睡眠柱状图（含目标虚线 / 缺失空心柱）
待处理卡片：待确认 · 冲突 · 未读提醒
最近记录与最近导入批次
```
- 交互：卡片可点进对应详情；时钟模式开启时整页换成表盘（§2.8）。

### 2.2 睡眠分析 `/sleep`
```
范围切换：7 / 30 / 90 天 ｜ 目标：7 小时（默认参考值 ⓘ）
参照范围卡：个人基线 + 「怎么算的」展开（中位数 ±2.5×MAD、覆盖率）
主图：每日夜间睡眠时长（柱）+ 目标虚线 + 缺失空心柱
睡眠阶段：深睡 / 浅睡 / REM（设备给比例就显示比例，不换算分钟）
明细表：最近 14 天（时长 / 阶段 / 状态 / 来源 / 修正）
```

### 2.3 指标趋势 `/trends`
```
左：指标选择器（P0 / P1 分组，provisional 带虚线问号）｜ 范围 7/30/90 天
参照范围卡（区间端点指标不显示）
主图：数值→折线 / 计数→柱 / 区间指标→上下限带（不画均值线）
统计条：均值 / 中位 / 最小 / 最大 / 有效天数 / 缺失率
固定提示：仅统计已确认记录；周/月记录不参与日趋势
```

### 2.4 导入 `/imports` → 预览 `/imports/preview`
```
三步条：① 上传 → ② 预览（不写库）→ ③ 写入（全部 pending）
预览页：横向计数条 + 五桶分区（冲突 → 待复核 → 拒绝 → 重复 → 可直接确认）
每行：行号 | 中文名+字段名 | 原始值→归一值 | 单位 | 错误码/标记 | 原因
底部固定操作条：写入 N 条（全部为 pending）+「写入后仍需确认」
```

### 2.5 记录 `/records` 与 冲突 `/conflicts`
```
记录：筛选（指标 / 状态 / 条数）+ 表格（日期 / 指标 / 值 / 状态 / 标记 / 操作）
操作：确认 · 驳回 · 改值 · 删除（均走 CSRF 表单）
冲突：同一日期同一指标新旧值并列，人工裁决（保留新 / 保留旧）
```

### 2.6 提醒 `/alerts`
```
顶部：未读数 · [立即评估] · 筛选（全部 / 未读 / 按规则）
卡片：规则名徽标 + 窗口 + 触发原因 + 建议 + 依据 N 条记录（可展开）+ 三条反馈
右侧常驻说明卡：同一窗口同规则只提醒一次，冷却 72 小时
空态二态：从未评估 / 评估过但无新增
```

### 2.7 报告 `/reports`
```
日报 / 周报切换（按日期取）
正文：关键数字（每个数字带来源记录数）+ 趋势一句话
可选：AI 改写（无密钥时用本地模板文案，不报错）
追溯：点数字可看依据记录
```
- 读路径不调 AI：只有点「改写」才发 POST。

### 2.8 时钟模式 `/chronos`
```
外环 6 扇区（睡眠/趋势/导入/提醒/报告/设置）+ 中心预览 + 「进入X」
交互：点扇区只预览，点「进入」才跳转；方向键切换；减少动态时瞬时切换
下方：普通入口 9 链接（不使用表盘也能到所有页面）
```

### 2.9 训练 `/training`

```
顶部：与首页同一张今日建议卡（同源，不另算）
记一次训练：日期 / 类型 / 部位 / 时长 / 主观强度 / 完成度 / 内容 / 备注
今天的状态：精力 1–5 / 疲劳 1–5 / 酸痛部位+程度 / 是否不适；同日覆盖更新
训练偏好：每周训练日 / 单次时间预算 / 器材 / 避练动作
最近训练：表格 + 删除（POST + CSRF）
```

### 2.10 设置 `/settings`
```
外观（简洁 / 时钟）→ 睡眠目标（只读 + 来源）→ 生活背景（6 项可留空）
→ 提醒阈值（只读表 + 环境变量名）→ 数据与隐私（导出/备份说明）→ 关于（版本/schema）
```

## 3. 数据来源

### 3.1 存储（SQLite，`data/health.db`）

| 表 | 内容 | 谁写 |
|---|---|---|
| `records` | 长表，唯一事实来源（值、单位、状态、标记、来源） | 导入、记录页操作 |
| `conflicts` | 同槽位异值，待裁决 | 导入时自动登记 |
| `import_batches` | 每次导入的文件与统计 | 导入写入 |
| `alerts` | 规则触发的提醒 + 反馈 | 规则引擎 |
| `baselines` | 基线计算快照（可选留档） | 计算/保存 |
| `settings` | 界面模式、生活背景 | 设置页 |
| `metrics_catalog` | 40 个指标定义 | `cli init` 种子 |
| `ai_call_log` / `report_cache` | AI 调用记账与报告缓存 | 报告页 |
| `audit_log` | 关键操作审计 | 确认/裁决等 |

### 3.2 页面数字的来源（不新造口径）

| 数字 | 函数 | 规则 |
|---|---|---|
| 指标卡数值 / 覆盖率 | `analytics.aggregate.summarize()` | 取窗口内**已确认**记录，最新一天为卡面值 |
| 参照范围 | `analytics.baseline.compute_baseline()` | 28 天窗口、≥14 天有效、中位数 ±2.5×MAD（MAD=0 用 IQR/1.349 兜底） |
| 趋势图 / 明细 | `load_points()` + `ui/charts.py` | 缺失留空不连线；区间指标只画带宽 |
| 待确认 / 冲突 / 未读 | `repository.count_records()` / 冲突表 / `alerts.count_unread()` | 计数实时查库 |
| 报告数字 | `reports.builder.build_daily/weekly()` | 每个数字带 `record_ids`，可追溯 |
| 提醒 | `rules.engine.run()`（4 条规则） | 阈值来自环境变量，冷却 72h |

**四条硬口径**：`NULL` 不是 0；`pending` 不进任何统计；`range_bound`（HRV/血氧上下限）不产生均值；`week/month` 记录不参与日趋势。

### 3.3 数据进来的唯一通道

华为运动健康截图 → 人工按六列 CSV/JSON 录入（`metric_name,record_date,value,unit,period_type,note`）→ `cli import` 或页面导入。
**不接**华为隐私中心加密包；不做设备直连。

## 4. 模块之间的交互

```
                 ┌──────────── 截图 → CSV/JSON ────────────┐
                 ▼                                         │
   [M1 导入] 上传 ──► 预览五桶（不写库） ──► 写入 batch + records(pending)
                                   │                       │
                                   │ 冲突行                 │
                                   ▼                       ▼
                             conflicts(待裁决)        [M1 记录页] 确认/驳回/改值
                                   │                       │
                                   └── 裁决 ──────────────► records(confirmed)
                                                           │
              ┌────────────────────────────────────────────┤
              ▼                        ▼                   ▼
      [M2 总览/睡眠/趋势]      [M3 报告]（读 confirmed）  [M3 提醒] 规则引擎
       summarize + baseline      数字带 record_ids        4 条规则 + 阈值
              │                        │                   │
              └──── 同一取数函数 ──────┘                   ▼
                                             alerts（冷却 72h）+ 反馈
   [M4 设置] ui_mode ──► 首页/导航换外壳（数据不变）
            阈值（环境变量）──► 规则引擎读取（页面只读展示）
   导出/备份：records 全表 → CSV/JSON / 整库 zip
```

关键点：
1. **单一事实来源**：所有页面读 `records` 的 `confirmed` 子集，没有第二套统计。
2. **确认是唯一闸门**：`pending` 不进统计、不进报告、不进提醒。
3. **模式只换皮**：`ui_mode` 只决定首页模板分支与导航样式；`/chronos` 与 `/` 共用 `context.dashboard_tiles()`。
4. **提醒不改数据**：只读统计结果 + 配置阈值，产出提示与反馈，不回写记录。
5. **报告不主动调 AI**：GET 只读缓存/本地模板；改写是显式 POST。

## 5. 配置项（`.env`，全部可选）

| 变量 | 作用 | 默认 | 必需 |
|---|---|---|---|
| `HEALTH_AGENT_DATA_DIR` | 数据目录 | `data` | 否 |
| `HEALTH_AGENT_DB_PATH` | 数据库路径 | `<数据目录>/health.db` | 否 |
| `HEALTH_AGENT_HOST` | 监听地址 | `127.0.0.1` | 否 |
| `HEALTH_AGENT_PORT` | 端口 | `8000` | 否 |
| `HEALTH_AGENT_LAN` | 允许局域网访问（`1` 开启） | 关闭 | 平板访问时必需 |
| `HEALTH_AGENT_PASSWORD_HASH` | 访问密码 hash（`cli passwd` 生成） | 无 | 开 LAN 时**强制** |
| `HEALTH_AGENT_SLEEP_TARGET_MIN` | 睡眠目标（分钟） | 420 | 否 |
| `HEALTH_AGENT_BASELINE_WINDOW_DAYS` | 基线窗口 | 28 | 否 |
| `HEALTH_AGENT_BASELINE_MIN_SAMPLES` | 基线最少有效天 | 14 | 否 |
| `HEALTH_AGENT_BASELINE_MAD_FACTOR` | 基线带宽倍数 | 2.5 | 否 |
| `HEALTH_AGENT_RULE_COOLDOWN_HOURS` | 同类提醒冷却 | 72 | 否 |
| `HEALTH_AGENT_SLEEP_DEFICIT_DAYS` | 睡眠不足触发天数 | 3 | 否 |
| `HEALTH_AGENT_RESTING_HR_SHIFT_BPM` | 静息心率偏移阈值 | 8 | 否 |
| `HEALTH_AGENT_DATA_GAP_RATE` | 缺失率阈值（0–1） | 0.5 | 否 |
| `AI_API_KEY` | AI 改写简报 | 无（用本地模板） | 否 |
| `AI_BASE_URL` / `AI_MODEL` | 接口地址 / 模型 | 内置默认（DeepSeek） | 否 |
| `AI_TIMEOUT_SECONDS` / `AI_MAX_RETRIES` | 超时 / 重试 | 20 / 2 | 否 |

> 阈值改了要重启才生效；设置页只显示当前值，不提供第二个修改入口（防止两处配置打架）。
>
> **例外：`AI_*` 三项可以在设置页里改**（「AI 分析接口」卡片）。保存时写回 `.env` 并重新装载，
> 立即生效、不用重启——这是唯一的可写配置项，因为它只影响"文案由谁改写"，
> 不参与任何统计、基线与提醒口径，改错了最坏的后果是文案退化成模板。
> 老名字 `DEEPSEEK_*` 仍然有效，两套同时存在时以 `AI_*` 为准。

## 9. 已知限制

- 只有本机/局域网访问，**没有 HTTPS、没有多用户**（上公网前必须先做）。
- 数据靠截图人工录入，没有设备直连。
- 40 个指标全部 `provisional`（未与厂商字段逐项核对）。
- 时钟模式无自由拖动旋转（零 JS 约束）。
- 提醒规则 4 条，阈值只能在 `.env` 改。
- 未验证：真机平板、Safari/Firefox、屏幕阅读器。
